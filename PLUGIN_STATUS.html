⚠️ CRITICAL: WebUI vs Desktop App

The Problem

qBittorrent WebUI CANNOT download from private trackers that require authentication.

Why: - WebUI sends download URLs directly to /api/v2/torrents/add - It bypasses nova2dl.py which handles authentication - Private trackers (RuTracker, Kinozal, NNMClub, IPTorrents) require login to download .torrent files - Result: Downloads appear to start but never actually begin

Works: - ✅ Plugins returning magnet links (most public trackers) - ✅ Desktop App with all plugins

Doesn’t Work: - ❌ Private trackers in WebUI (RuTracker, Kinozal, NNMClub, IPTorrents)

Merge Search Service

NEW: A merged search service that aggregates results from all trackers.

Service Status

Component Status Port
FastAPI Server ✅ Running 8086
Download Proxy ✅ Running 8085
qBittorrent WebUI ✅ Running 8085

Features

  • Unified Search: Searches all 35+ plugins simultaneously
  • Smart Deduplication: Merges identical torrents by infohash, name+size, or fuzzy matching
  • Real-time Streaming: SSE updates every 500ms
  • Metadata Enrichment: OMDb, TMDB, TVMaze, AniList, MusicBrainz, OpenLibrary
  • Tracker Health: Validates trackers via HTTP/UDP scrape
  • Event Hooks: Execute custom scripts on search/download events
  • Scheduling: Automated recurring searches with persistence
  • Web Dashboard: UI at /config/download-proxy/src/ui/templates/dashboard.html

API Endpoints

POST /api/v1/search          - Execute merged search
GET  /api/v1/search/stream/{id} - Stream results (SSE)
GET  /api/v1/search/{id}    - Get search status
GET  /api/v1/downloads/active - Active downloads
GET  /api/v1/hooks           - List hooks
POST /api/v1/hooks           - Register hook
GET  /health                 - Health check

Usage Example

# Search across all trackers
curl -X POST http://localhost:8086/api/v1/search \
  -H "Content-Type: application/json" \
  -d '{"query": "Ubuntu 22.04", "limit": 50}'

# Stream results
curl -N http://localhost:8086/api/v1/search/stream/{search_id}
