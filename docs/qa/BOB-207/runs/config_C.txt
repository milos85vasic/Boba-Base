DECLARED GAPS — not covered by this unit suite, by measurement not by choice:
  * A real host-UID mismatch (the observed uid-100999 defect) cannot be
    seeded unprivileged: chown -> EPERM, unshare -Ur chown -> EINVAL, and
    unshare --map-users over the real subuid range -> EPERM (all measured
    2026-08-21). An unprivileged process also could not repair such an item
    back, so no implementation could turn that fixture green here. Covered
    by tests/ownership/test_container_writes_owned_files.py instead.
  * A genuine chown/chgrp EPERM on an EXISTING item (the real-world failure
    mode behind FR-006) needs a foreign-owned file, which is the same
    privilege gap. Case 7 uses the absent-non-optional-path route, which is
    real and deterministic but exercises a different code path than EPERM.
  * FR-004d blocking-before-services and FR-004e real progress output are
    integration-layer properties and are deliberately not asserted here.
  * The preserve_mode:TRUE symlink path WAS broken and is now covered
    by Case 9: a bare chmod follows a symlink on Linux (there is no -h),
    and a symlink's find %m is 777, so the mode-restore step moved an
    OUT-OF-SCOPE target from 600 to 777. Measured and fixed 2026-08-21.
